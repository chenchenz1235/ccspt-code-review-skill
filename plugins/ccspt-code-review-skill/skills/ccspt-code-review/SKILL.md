# CCSpt 审核工具集

本入口负责选择专项、共享项目上下文和汇总结果。专项的规则、计算脚本与模板分别维护，避免加载与本次任务无关的内容。

## 选择专项

| 目标 | 读取的入口 | 产物 |
|---|---|---|
| 电机参数、派生公式、硬件系数、参数与保护关联 | [电机参数审核](../ccspt-motor-parameter-review/SKILL.md) | 单文件离线 HTML |
| 解释或生成压缩机温控动作规则 | [温控逻辑](../ccspt-thermostat-logic/SKILL.md)，模式 A | 中英双语 Markdown |
| 核对客户温控要求与实现 | 同上，模式 B | 逐条核对 Markdown |
| 检查温控状态机、计时器、启停统计或故障恢复 | 同上，模式 C | 缺陷与待确认项 Markdown |

- 用户已明确任务时直接加载对应专项；只说“审核整个工程”且范围不明时，先按目录与已有资料识别候选目标，再补齐影响执行的范围信息，不默认开展所有专项。
- 同时要求多个专项时，共享用户已提供的工程版本、硬件资料和约束，各专项保留自己的前置条件与输出格式。不要因参数专项使用 HTML 而强制温控文档改成 HTML。
- 执行参数审核前遵循参数专项的版本检测和立项单要求。缺少其必要资料时仅暂停该专项；用户已授权且资料齐全的温控工作可以继续。客户要求缺失时不能执行温控模式 B，不能将模式 C 的结果冒充需求核对。
- 两专项涉及同一保护、参数或时序时，注明关联并避免重复计数；不能把参数审核通过当作状态机已验证。
- 超出已有专项的任务先明确当前覆盖边界。用户明确要求其他代码审查时按用户规则开展，并标明没有本工具集专项规则支持。

## 执行与交付

默认只读源工程，按用户要求生成产物。修复代码、修改模型、安装更新或上传项目资料需要相应授权；任务中已经给出的授权继续有效。

先检查专项入口是否可读，再执行其流程。缺少相邻专项目录时说明安装不完整，不从文件名猜测规则。使用插件安装或将三个 skill 目录一起放入同一 skills 父目录，可保持上述相对引用有效。

单专项直接交付对应结果。综合任务在答复中简要汇总各专项的实际读取范围、版本、确认问题、待确认项、未检查内容及产物位置；不额外生成用户未要求的综合报告。
